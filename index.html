About

Profile

Six years in, and the part I still like best is the part underneath — sockets, schedulers, storage layers, the things that decide whether a system holds up at 3am. I spent a year as a consultant building a mobile app, then moved onto platform engineering for an Italian telecom company, running Kubernetes infrastructure and internal tooling for other engineers.

Alongside full-time work I went through 42 Roma Luiss, which is where the low-level habits come from: writing an HTTP server without a framework, a shell without a library, a renderer without an engine. Right now I'm studying again — a different field, a different university — mostly because stopping felt worse than being busy.

The through-line is the same either way. Read the spec, understand the constraint, then build the smallest thing that actually satisfies it.

Python · Qdrant

Distributed RAG Document Synthesis Platform

Source ↗

A common data environment that reads your documents and writes new ones — ingest, chunk, embed, retrieve, then synthesise against a template. Every stage is containerised and independently observable.

  • Built a containerised RAG backend on LlamaIndex for document chunking and metadata extraction, with each stage isolated behind its own service boundary.
  • Used Qdrant — a Rust vector database — for high-dimensional similarity search, keeping k-NN latency off the request path of ingestion.
  • Decoupled storage from day one: MinIO for raw objects, PostgreSQL for metadata, so write scaling and blob scaling are independent problems.
  • Wired the whole pipeline into Promtail → Loki → Grafana, because a synthesis step that fails silently is worse than one that fails loudly.

C++ · POSIX

An HTTP/1.1 Server, Written From Nothing

Source ↗

No framework, no library, no threads. One process, one select() loop, and up to 1024 concurrent file descriptors — all of them allowed to stall halfway through a read or a write without taking the server down.

  • Bypassed every web framework and wrote the event loop and the HTTP request parser by hand in C++.
  • Single-threaded, non-blocking I/O multiplexed with select(), holding up to 1024 file descriptors without a thread per connection.
  • State-machine logic for partial socket reads and writes (EAGAIN), CGI execution via fork(), and memory safety under sustained stress.
  • C++

Dining Philosophers, At The OS Level

Source ↗

Resource contention with no safety net: no deadlock, no livelock, no starvation, and no thread quietly winning at the expense of another. The interesting part is not the solution — it's proving the solution holds.

  • Managed OS-level concurrency directly in C with POSIX threads and hand-placed mutexes.
  • Fine-grained locking on every shared resource — forks and stdout alike — so logging could not itself become the race.
  • Timing verified against death thresholds, because a philosopher that eats late is a correctness bug, not a performance one.

A UNIX Shell, One Global Variable Allowed

Source ↗

Lexing, parsing, process lifecycle, and signal handling — with exactly one global permitted, reserved for signal state. Every other piece of context has to be threaded through by hand.

Cub3D — A Raycasting Engine In C

Source ↗

A convincing 3D world drawn from a flat 2D grid, one ray per screen column. Wolfenstein's trick, rebuilt: DDA traversal, fish-eye correction, and per-column texture sampling inside a tight pixel-buffer loop.

  • Perpendicular wall distance correction to remove fish-eye distortion, with directional texture mapping for N/S/E/W faces.

CoreQ

Automated quotation & production management · Manufacturing SMEs

A quoting and production system for small manufacturers, replacing a legacy MySQL codebase with PostgreSQL and FastAPI. The design shift that matters is a bottom-up data model: operations bind to parts, parts to quotes, quotes to orders. Nothing floats in a vacuum any more.

On top of that sit a virtual machine park — digital twins carrying hourly rates and physical constraints — material twins priced against live LME data, and a cascading analytics layer where SQL views compute margins and client whale scores without anyone touching a spreadsheet.
